# Create and convert workflows

- **Create:** Honor an explicit Umbraco version. Otherwise inspect installed `Umbraco.Templates` packages with `dotnet new uninstall`; use the installed `umbraco` template when its version is 17 or newer. If none is installed or the installed version is older than 17, select and install a verified stable 17+ template compatible with the available SDK. Reject versions below 17 and preview versions unless the user explicitly requests a preview. Record the exact template version and verify the generated CMS package version and target framework before continuing; never silently upgrade or downgrade to a different major. Run `dotnet new umbraco` with no SQLite development database. Create the Aspire AppHost and local settings described in [topology.md](topology.md). Choose the AppHost form before scaffolding: a project-based host uses `Properties/launchSettings.json`, while a single-file host uses its run settings. In the 13.5.4 trial, `aspire new aspire-empty` generated a single-file host; if a project-based host is needed, scaffold it directly. Verify that the Development profile and `aspire.config.json` point to the AppHost you will run. For a new multi-project solution, check whether the Umbraco template generated a project-local `Directory.Packages.props`. NuGet uses the nearest file, so either keep all web package versions there or consolidate them into a solution-level central file; do not add package versions only at the solution root while a nearer file still shadows them. Do not change a converted project's existing package convention.
- **Convert:** Identify the effective Umbraco package version from the project and its central package file, then determine the effective `umbracoDbDSN` connection string and `umbracoDbDSN_ProviderName` from the project's configuration providers. Check development overrides, user secrets, and environment values without printing credentials. If the project is below Umbraco 17, stop and report the version. If its effective provider is SQLite, stop **before changing any file**; tell the user to migrate the database to SQL Server and return. If the provider is unknown, resolve it with the developer before editing. For SQL Server, verify version 2022+ if a connection is available; otherwise report that prerequisite. Retain the project's Umbraco version, database, and configuration; do not create a replacement database or copy data.
- Before a conversion edit, copy the original `Properties/launchSettings.json` to a nonclobbering adjacent backup name such as `launchSettings.pre-umbraco-local-topology.json` (add a numeric suffix if needed). Merge the new profiles into the original valid JSON. Preserve unrelated profiles, values, project references, startup behavior, and package conventions. On repeated use, update only this skill's profiles and avoid accumulating backups when no edit is needed.
