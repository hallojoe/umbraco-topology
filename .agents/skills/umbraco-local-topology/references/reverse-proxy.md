# Optional local YARP entry point

Read only when the user requests a reverse proxy. Add a small YARP project named `<solution namespace>.Yarp`, following the target solution's project layout and package convention. Add it to the solution and AppHost. Do not import the nearby reference app's SAML, authentication, or other unrelated routes.

Listen on HTTPS port `4443`. Route `cm.dev.localhost` to CM only, and `cd.dev.localhost` to both Subscribers. Set the CD cluster's `LoadBalancingPolicy` to `RoundRobin`; add cookie session affinity with `Redistribute` failure behavior so a user's session can remain on a CD instance. Preserve the original host header and the externally visible HTTPS scheme. AppHost should supply destinations from its CM/CD endpoint references, wait for those projects, and avoid hardcoded ports inside YARP configuration when Aspire can provide endpoints.

Set CM's public `BackOfficeHost` and `UmbracoApplicationUrl` to `https://cm.dev.localhost:4443` and CDs' `UmbracoApplicationUrl` to `https://cd.dev.localhost:4443/`. Keep each instance's private listen address distinct. Set the Subscribers' backoffice host to the CM public origin only if the site's existing behavior requires links to it; do not point it to a Subscriber. Enable ASP.NET Core forwarded headers in the Umbraco app before middleware that uses host, scheme, or client IP. Accept `X-Forwarded-For`, `X-Forwarded-Host`, and `X-Forwarded-Proto` only from the trusted local YARP endpoint or loopback network; do not clear trusted proxy/network lists globally.

Check both certificate trust **and certificate host coverage** for `cm.dev.localhost` and `cd.dev.localhost`. A trusted `localhost`-only development certificate is insufficient for these names. Configure YARP with a locally trusted certificate whose SAN contains both names, using a cross-platform path appropriate to the developer's OS; never disable TLS validation or silently install a new trust root. If no suitable certificate is available, report the exact certificate step needed and make YARP opt-in until it is configured, so the default direct CM/CD AppHost still starts.

Verify that CM's backoffice opens on the CM host, CD traffic reaches both Subscribers, redirects keep the public host and HTTPS scheme, and a session remains usable across requests. Inspect YARP's response or logs to distinguish the two CD destinations during the round-robin check; do not infer distribution from identical page output.
